KEY IMPLEMENTATION PATTERNS - GFL (Template for Trade Finance)
================================================================================

1. SKIP SECURITY QUESTIONS
   ────────────────────────
   Location: ProfileStateCheckServiceImpl.ifToUnblockOnBoardingProfile()
   
   How it works:
   - Method has parameter: boolean isCheckSecurityQuestionsSetUp
   - If FALSE: Security questions check is bypassed ✅
   - If TRUE: Security questions must be present
   
   GFL Usage:
   - When validating Cellulant PIN: pass false
   - When setting up PIN: pass false (skip security questions entirely)
   
   Code:
   ┌────────────────────────────────────────────────────────┐
   │ boolean isByPassSecurityQuestionsSetUpCheck = true;    │
   │ if (isCheckSecurityQuestionsSetUp) {                   │
   │     isByPassSecurityQuestionsSetUpCheck =              │
   │         profile.getSecurityQuestions() != null &&      │
   │         !profile.getSecurityQuestions().isEmpty();     │
   │ }                                                      │
   │ // If false param: check is bypassed ✅                │
   └────────────────────────────────────────────────────────┘
   
   Trade Finance Usage:
   - REUSE THIS EXACT PATTERN ✅
   - Pass false to skip security questions


2. NO CELLULANT VALIDATION
   ───────────────────────
   Location: ProfileCountryAndPhoneNoServiceImpl.validateCellulantPin()
   
   How it works:
   - GFL does NOT call validateCellulantPin() at all
   - PIN is set directly in Profile entity
   - Cellulant interaction is skipped
   
   Current Problem:
   - No clear conditional check currently
   - Cellulant validation is implicit in flow
   
   Solution for Trade Finance:
   - Extract Cellulant validation into conditional block:
   
   ┌────────────────────────────────────────────────────────┐
   │ if (client.shouldValidateCellulantPin()) {             │
   │     StatusCodeAndException result =                    │
   │         cellulantService.validateCellulantPin(...);    │
   │     // Process result                                  │
   │ } else {                                               │
   │     // Skip Cellulant, set PIN directly                │
   │     profile.setPinSet(true);                           │
   │ }                                                      │
   └────────────────────────────────────────────────────────┘


3. FIORANO DATA PULL
   ──────────────────
   Location: FioranoDataQueryServiceImpl
   
   Method: getCustomerCoreBankingAccountsByIdNumberOrPassport(idNumberOrPassport)
   
   How it works:
   - Try National ID first
   - Fall back to Passport if not found
   - Returns customer details from Fiorano
   
   GFL Usage:
   - Used for onboarding to pull customer data
   - Maps Fiorano response to Profile
   
   Trade Finance Usage:
   - REUSE THIS EXACT METHOD ✅
   - Primary source (not fallback)
   - Input: National ID or Passport from USSD user
